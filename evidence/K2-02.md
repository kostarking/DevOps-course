# K2-02. Свой Dockerfile — 7 баллов

## Файл и команды

Файл `lab/Dockerfile` использует `python:3.13-slim-bookworm`, задаёт `LABEL course.student="barbarich"`, копирует `app.py` и `index.html`, подготавливает `/data`, запускает приложение от `10001:10001`, документирует `8000` и использует `CMD ["python", "app.py"]`.

```bash
docker build -f lab/Dockerfile -t devops-student:v1 lab
docker image inspect devops-student:v1
docker run --rm -d --name student-web -p 127.0.0.1:8081:8000 -e ROLE=web devops-student:v1
curl -i http://localhost:8081/health
docker logs student-web
docker stop student-web
```

## Наблюдение

Сборка завершилась с кодом 0. `docker image inspect` вывел метку `course.student=barbarich`, пользователя `10001:10001`, команду `python app.py` и порт `8000/tcp`. Запущенный контейнер ответил на `/health` кодом HTTP 200 и телом `{"process": "running", "role": "web"}`. В логах видны событие `started` и запрос `/health` с кодом 200. После `docker stop` контейнер отсутствовал в `docker ps -a`, так как был запущен с `--rm`. Выводы команд находятся в `K2-02/`.

## Вывод

Успешная сборка и найденная метка подтверждают, что Docker применил инструкции Dockerfile и добавил идентификатор студента к образу. Ответ 200 показывает, что процесс приложения запущен и HTTP-сервер отвечает на проверку состояния. `--rm` автоматически удаляет остановленный контейнер, но не образ.

`COPY` переносит файлы из build context в образ, `CMD` задаёт процесс по умолчанию, `USER` выбирает непривилегированного пользователя, `RUN ... chown` даёт ему права на `/data`, `LABEL` хранит код студента, а `EXPOSE` только описывает внутренний порт. Для доступа браузера нужен `-p`, который связывает порт хоста с портом контейнера.
