# K2-05. Ошибка конфигурации — 3 балла

## Воспроизведение ошибки

Временно в `compose.student.yaml` было установлено `API_URL: http://api:9999`, после чего выполнено:

```bash
docker compose -f compose.student.yaml up -d web
curl -i http://localhost:8080/api/requests
docker compose -f compose.student.yaml logs web
```

### Наблюдение

Ответ на GET списка был HTTP 503 с телом `{"error": "upstream_unavailable"}`. В логе `web` зафиксированы `target: "http://api:9999"` и `Connection refused`. `docker compose ps` при этом показывал `web` в состоянии `Up` и `healthy`, а `api` — `Up` и `healthy`. Выводы сохранены в `K2-05/bad-response.txt`, `bad-web.log` и `bad-ps.txt`.

### Вывод

Состояние `healthy` подтверждает только доступность собственного health endpoint контейнера `web`, но не успешное выполнение запроса к API. Ошибка возникла потому, что `web` пытался подключиться к порту 9999, где API не слушает; поэтому TCP-соединение было отклонено и приложение вернуло 503.

## Исправление

Значение возвращено к `API_URL: http://api:8000`, затем выполнено:

```bash
docker compose -f compose.student.yaml up -d web
curl http://localhost:8080/api/requests
curl -X POST http://localhost:8080/api/requests -H 'Content-Type: application/json' -d '{"kind":"screen","key":"kt2-fixed-20261030-1000"}'
```

### Наблюдение

После исправления GET списка вернул HTTP 200 и данные заявок, а POST вернул подтверждение новой заявки №8. Итоговый `docker compose config` показывает `API_URL: http://api:8000`; состояние контейнеров и HTTP-ответы сохранены в `K2-05/`.

### Вывод

Успешные GET и POST после восстановления порта подтверждают связь `web` с API и приём новой заявки. Внутри сети Compose `web` должен обращаться к `api:8000`: `8000` — порт процесса API в контейнере. `8080` — опубликованный порт хоста для доступа к `web` из браузера.
