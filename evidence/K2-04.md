# K2-04. Registry — 4 балла

## Команды

```bash
docker compose --profile registry up -d registry
docker tag devops-student:v1 localhost:5000/workshop:v1
docker push localhost:5000/workshop:v1
docker pull localhost:5000/workshop:v1
docker image inspect localhost:5000/workshop:v1
```

## Наблюдение

В выводе Compose локальный сервис registry перешёл в состояние `Running`. `docker image ls` показал имена `devops-student:v1` и `localhost:5000/workshop:v1` с одним ID образа. `docker push` завершился строкой `v1: digest: ...`, а `docker pull` подтвердил получение образа и тот же digest. `docker image inspect` показал тег и RepoDigest. Digest текущего образа:

```text
sha256:cb19dda2bb2890126843effb0faa5a2daac8b831e07960c5dc80487d7c31b0a0
```

Значение совпадает в выводах push, pull и inspect; полные результаты сохранены в `K2-04/`.

## Вывод

Совпадение ID после `tag` показывает, что добавлено ещё одно имя того же локального образа. Успешные push и pull подтверждают передачу образа в registry и обратно. Tag — изменяемое человекочитаемое имя, а digest — идентификатор содержимого, однозначно фиксирующий точный вариант. Контейнер после push не запустился, потому что push только сохраняет образ в registry; для запуска нужна отдельная команда `docker run` или Compose.
