# K2-03. Compose и сохранность данных — 7 баллов

## Команды

```bash
docker compose -f compose.student.yaml config
docker compose -f compose.student.yaml up -d
curl -X POST http://localhost:8080/api/requests -H 'Content-Type: application/json' -d '{"kind":"battery","key":"kt2-first-20261030-1000"}'
docker compose -f compose.student.yaml up -d --no-deps --force-recreate api
curl http://localhost:8080/api/requests
curl -X POST http://localhost:8080/api/requests -H 'Content-Type: application/json' -d '{"kind":"software","key":"kt2-second-20261030-1000"}'
```

## Наблюдение

`docker compose config` успешно разобрал файл. В итоговой конфигурации оба сервиса используют `devops-student:v1`, `web` имеет `API_URL=http://api:8000`, а `api` подключает именованный том `kt2student_requests` к `/data`. Список `docker compose ps` показал оба контейнера в состоянии `Up`, `api` — `healthy`, и публикацию `127.0.0.1:8080->8000/tcp` у `web`. POST вернул заявку №6; после `--force-recreate api` GET вернул её же в списке. Следующий POST создал заявку №7. Inspect до и после пересоздания показал разные ID контейнера API и то же подключение тома. Подтверждения лежат в `K2-03/`.

Дополнительно: старый остановленный контейнер `web` не восстановил публикацию `8080` при `start`, поэтому перед основной проверкой он был пересоздан по текущей конфигурации. После этого `docker compose ps` показал опубликованный порт, а `/health` вернул HTTP 200.

## Вывод

Сохранение заявки №6 при смене ID контейнера показывает, что данные хранятся вне файловой системы контейнера API: в именованном томе, подключённом к `/data`. Без отдельного тома база находилась бы в слое старого контейнера и пропала бы при его замене. `API_URL=http://api:8000` использует DNS-имя сервиса Compose и внутренний порт API. Порт `8080` доступен браузеру на хосте и перенаправляется в `web:8000`; контейнеры между собой обращаются к `api:8000`, а не к порту хоста.

Запуск: `docker build -f lab/Dockerfile -t devops-student:v1 lab`, затем `docker compose -f compose.student.yaml up -d` и открыть `http://localhost:8080`.
