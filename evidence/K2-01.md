# K2-01. Образ и контейнер — 4 балла

## Команды

```bash
docker image inspect devops-course:base
docker compose -p kt2original -f compose.yaml ps
docker compose -p kt2original -f compose.yaml stop web
curl -i --max-time 4 http://127.0.0.1:8080/
docker compose -p kt2original -f compose.yaml start web
curl http://127.0.0.1:8080/health
curl -X POST http://127.0.0.1:8080/api/requests -H 'Content-Type: application/json' -d '{"kind":"screen","key":"k201-20261030-0955"}'
```

## Наблюдения

`image inspect` показал образ `devops-course:base`, рабочую папку `/app`, команду `python app.py`, пользователя `10001:10001` и порт `8000/tcp`. Вывод сохранён в `K2-01/image-inspect.txt`.

`compose ps` показал два контейнера проекта: `kt2original-api-1` с ролью `api` и `kt2original-web-1` с ролью `web`; веб-сервис опубликован как `127.0.0.1:8080->8000/tcp`. После `stop web` запрос завершился `curl: (7) Failed to connect`. После `start web` `/health` вернул `{"process": "running", "role": "web"}`, а POST создал заявку №2. Точные выводы сохранены в каталоге `K2-01/`.

## Вывод

Остановка `web` остановила только веб-контейнер: пользовательская страница стала недоступна, но `api` оставался отдельным контейнером. После повторного запуска веб-часть снова связалась с API и приняла заявку. Образ при остановке не удаляется: это отдельный объект Docker, который исчезает только после явной команды удаления.
